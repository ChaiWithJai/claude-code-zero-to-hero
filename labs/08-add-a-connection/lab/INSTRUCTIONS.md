# Choose a useful connection

Choose one connection by purpose, access, a bounded test, and a fallback.

## Try it

1. Read inputs/connection-cards.txt. Start with a useful artifact you already understand.
2. Choose one capability: browser, Calendar, Mail, Docs, Sheets, or Slides. State the purpose before the tool.
3. Record the current access status and any required approval.
4. Describe a bounded test and a local-file fallback. Do not connect an account just to finish this reflection.
5. If you already have approved access, inspect a single reversible test result. Otherwise record the plan as planned.

## Keep

Save your output in `outputs/`. Keep your prediction, source checks, model revision, and evidence route in `outputs/NOTES.md`. Your notes can stay private.

## Check

- Does the connection unlock something your wish needs?
- Is the status honestly planned, blocked, or tested?
- Can useful work continue with a local file?

The launcher offers hints, examples, and a work check. A check of an open-ended note is a prompt for review, not a grade.
